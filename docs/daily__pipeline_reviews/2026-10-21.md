## 异常与根因

- 异常：旧导出声明 `newest_id=1782103537234973176`，文件实际最大 ID 为 `2107430866498769297`。
  - 根因：旧版 `newest_id` 取 `allTweets[0].id`（插入顺序），不是雪花 ID 最大值。
  - 证据路径：`x-archive inspect inbox/processed/bookmarks_Ethan151300_20261007-125020_20261007-130157.json` 输出。
  - 下一步：v2.0.0 起改为 `BigInt` 最大值；新导出应满足 `declared.newest_id == actual.newest_id`。
- 异常：旧导出 1,076 条空文本、3,245 条 `unknown` 作者。
  - 根因：采集器把 `user_results` 的 `User` 节点当成 Tweet，且作者字段迁移到 `core.screen_name` 后未适配。
  - 证据路径：同一份旧导出；`scripts/check-userscript.mjs` 的新旧对照实验。
  - 下一步：只能用 v2.2.0 重新导出；本地无法恢复作者。
- 异常：真实运行 11 屏无新增，导出 54 条而非 80 条。
  - 根因：`startSync()` 的 `tweetCollector.clear()` 丢弃了页面预加载的第一页（26 条）；第一页不会因滚动重新请求。
  - 证据路径：用户运行日志（15:54:35 +26；15:55:19 开始；15:55:21–15:55:41 共 11 屏 0；15:55:41 +25；15:56:07 +29；15:56:10 导出 54）。
  - 下一步：v2.2.0 保留首屏；新增 `startSync` 行为测试断言采集器不被清空。
- 异常：手工清理 e2e 数据后 `verify` 报 `foreign_keys: 4 violation(s)`。
  - 根因：Python `sqlite3` 默认 `foreign_keys=OFF`，裸 `DELETE FROM tweets` 未触发级联，`archive_entries`/`tweet_media` 留下孤儿；同时误删一条真实推文。
  - 证据路径：`x-archive verify` 输出；`backups/x-archive-20261021-150015.sqlite3` 恢复记录。
  - 下一步：破坏性操作统一走 CLI；如必须裸 SQL，先备份并显式 `PRAGMA foreign_keys=ON`。

## 建议调整

- 破坏性数据库维护只使用 `x-archive prune` / `x-archive forget`，不直接写 SQL；如必须写 SQL，先备份、显式开外键、事后 `verify`。
- 采集器改动必须先核对用户真实 URL 与实际 GraphQL 操作名；`@match` 与端点白名单都要有行为测试覆盖。
- 开始抓取不得清空页面预加载数据；按页面类型维护成员关系，避免 Bookmarks/Likes 互串。
- 触底超时应大于真实分页延迟（当前 40s），并把“等待下一页”显式写入日志，避免被误判为卡死。
- 发布前补真实浏览器 E2E（Playwright + 专用测试账号），Node VM 测试不能替代真实会话。
- `README.md` 保留为产品文档；project-save 的活性摘要放在 `Handover Book.md` 与日复盘，不覆盖 README。
